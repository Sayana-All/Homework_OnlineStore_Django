# Homework_OnlineStore_Django
### Создание онлайн-магазина с помощью фреймворка Django

## Описание
Создаем веб-приложение интернет-магазина с помощью фреймворка.

Необходимо настроить новый проект Django, создать и зарегистрировать новое приложение, а также реализовать первые страницы с использованием шаблонов и контроллеров.

Далее нужно подключить PostgreSQL к проекту, создать и настроить модели `Product` и `Category`, перенести их в базу данных с помощью миграций, 
зарегистрировать и настроить модели в админке, наполнить базу данных через Django shell, создать фикстуры для моделей и реализовать кастомную команду для добавления тестовых данных.

##### Homework_23
+ Подключена и настроена база данных _"dj_catalog"_ через СУБД PostgreSQL.
+ В модуле **models.py** созданы 2 модели для приложения с возможностью наполнения данными: `Product` и `Category`.
    * в модели(классе) `Product` есть поля: наименование, описание, изображение, категория, цена за покупку, дата создания и дата последнего изменения;
    * в модели(классе) `Category` есть поля название и описание. Реализована возможность выбирать продукты по категориям.

    * для класса `ProductAdmin` настроено отображение _id_, _name_, _price_ и _category_ в списке, фильтрация по категориям, доступен поиск по названию и описанию категории.

+ Сформированы фикстуры для моделей `Category` и `Product` и сохранены в файле **catalog_fixture.json**.
+ Создана кастомная команда в модуле **add_test_models.py** для добавления тестовых продуктов.
Кастомная команда загружает тестовые категории и продукты из фикстуры **catalog_fixture.json**, предварительно удаляя все существующие данные из базы.

##### Homework_25
+ Все имеющиеся в проекте контроллеры переведены с FBV на CBV. Реализован полный CRUD для приложения:
    * шаблон домашней страницы переименован в (`product_list.html`), доступен со стартовой страницы;
    * контроллер с детальной информацией теперь носит название `ProductDetailView`, доступен по старому адресу;
    * контроллер для добавления нового продукта переименован в `ProductCreateView`, реализован через HTML-шаблон (`product_form.html`) и доступен по адресу `create/`;
    * добавлен новый контроллер `ProductUpdateView` для редактирования существующего продукта, реализован через HTML-шаблон (`product_form.html`) и доступен по адресу `product_detail/<int:pk>/edit`;
    * добавлен новый контроллер `ProductDeleteView` для удаления выбранного продукта, реализован через HTML-шаблон (`product_confirm_delete.html`) и доступен по адресу `product_detail/<int:pk>/delete`;
    * дополнительный контроллер с контактной информацией переделан в `ContactsTemplateView`, доступен по старому адресу и принимает сообщение от пользователя для обратной связи.

+ Создано новое приложение для блога **blog**, весь его функционал доступен по адресу `/blog/...` 
+ В модуле **blog/models.py** создана модель для блоговой записи `BlogArticle`.
В этой модели(классе) есть поля: заголовок, содержимое, превью(изображение), дата создания, признак публикации(`is_publication`) и количество просмотров.
+ Реализован полный CRUD для модели `BlogArticle`.
+ Модифицированы некоторые методы для стандартных контроллеров:
  * в контроллере `BlogArticleListView` установлена фильтрация для вывода в список только опубликованных статей;
  * при открытии отдельной статьи через `BlogArticleDetailView` увеличивается количество её просмотров;
  * в контроллере `BlogArticleUpdateView` изменены переадресация: после успешного редактирования записи пользователь будет перенаправлен на просмотр этой статьи.

##### Homework_26.1
+ Реализован механизм CRUD для модели продуктов и блога, используя модуль **forms.py**.
+ Для формы продуктов `ProductForm` реализована валидация формы, чтобы проверять отсутствие запрещенных слов (в любом регистре) в полях имени и описания товара.

Если использованные запрещенные слова, то выводится информационное сообщение пользователю с указанием ошибки.
+ Для формы продуктов `ProductForm` добавлена кастомная валидация для поля `price` с использованием метода`clean_price` и доступна в форме создания и редактирования продуктов.
Если цена введена неправильно, выводится соответствующее сообщение пользователю.
+ Оформлена стилизация форм для продуктов и блога, используя метод `__init__`.

##### Homework_27
+ Создано новое приложение для работы с пользователями **users**, весь его функционал доступен по адресу `/users/...` 
+ В модуле **users/models.py** создана модель пользователя `User`.
В этой модели(классе) есть поля: email, номер телефона(необязательное поле), страна(необязательное поле), аватар(изображение), токен(для подтверждения почты).
Email используется как основное поле для регистрации и авторизации. 
+ Реализован механизм авторизации с использованием стандартных контроллеров `LoginView` и `LogoutView`:
  * вход на сайт доступен по почте и паролю пользователя через шаблон (`login.html`) и кнопку в меню навигации, после авторизации перенаправляет на главную страницу приложения **catalog**;
  * выход из профиля доступен по соответствующей кнопке в меню навигации, после выхода перенаправляет на главную страницу с.
+ Реализован механизм регистрации пользователя с помощью контроллера `UserCreateView`:
  * контроллер использует форму для регистрации пользователя `UserRegisterForm` с полями электронной почты, пароля и его подтверждением;
  * форма для регистрации пользователя использует HTML-шаблон (`registration_form.html`) и доступна по кнопке в меню навигации;
  * в представлении переопределен метод для валидации `form_valid` с отправкой подтверждения регистрации на почту пользователю (для сервиса Yandex!!!);
  * дополнительный контроллер `email_verification` открывает вход на сайт только после прохождения по ссылке для подтверждения почты из письма.
+ Ограничен доступ к страницам, связанным с управлением продуктами, для анонимных пользователей. 
Теперь только авторизованные пользователи могут просматривать, создавать, изменять и удалять продукты и статьи в приложениях **catalog** и **blog**.
При попытке воспользоваться недоступным функционалом неавторизованных пользователей будет перенаправлять на страницу входа на сайт.
+ В приложении **blog** для модели статьи `BlogArticle` добавлено поле _Автор_, доступное по внешнему ключу и отраженное в карточке статьи. 
Добавляется автоматически при создании новой статьи, где указывается добавивший её пользователь.

##### Homework_29
+ Установлен и настроен _Redis_ как брокер для кеширования.
+ В приложении **catalog** сделан ряд улучшений:
  * настроено кеширование для страницы контроллера `ProductDetailView`;
  * добавлено низкоуровневое кеширование для списка продуктов и вынесено в сервисный слой через класс `ProductService`;
